# M2.T6: Allocate backing and commit credit with its event

Status: planned; no implementation in this change.

**Outcome:** Each successful manual drain or quoted payment creates one fully backed credit and its
event atomically.

**Learn:** Exclusive backing, liability, allocation and the transactional outbox pattern.

- Depends on: [M2.T5](M2.T5.md), [M1.T2](M1.T2.md).
- Primary journey ownership: J2.S5, J3.S5, J8.S7.
- Policy: D21, D23, D121, D125–D127, D230. Invariants: I1, I4, I10.
- Rough effort: 2–3 focused developer days, excluding external waits.
- Expected locations: packages/server/src/settlement and outbox persistence.

Read the linked [decisions](../decisions.md), exact criteria in the
[journey spine](../journeys/settle-kit.yaml), and [technical

Use the [checkpoint protocol](README.md#how-we-implement-together). Implement one

## Checkpoint 1: Allocate backing using the correct money rule

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement one exclusive allocator with manual full-net and quoted fixed-credit paths. Key
manual credit to its observed drain and quoted credit to paymentId. Record quoted host residual and
separately verified shortfall funding.

**Check:** Use reordered/duplicate evidence under I1/I10. Reject already allocated funding and keep
quote_shortfall uncredited (J8.S6.c5–c6, J8.S7.c1–c3).

**Walk through:** Why may a quote leave a host residual while a manual deposit credits the full
verified net?

## Checkpoint 2: Commit the credit and event together

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Under the chain-pause lock, claim source/backing and insert the immutable credit,
allocations, outbox body and pending delivery. Include required account, payment and chain
identities in the event.

**Check:** Race two credit workers and inject failure between every write (J2.S5.c8–c10,
J3.S5.c8–c10, J8.S7.c1–c2). Real Postgres must produce one backed result or complete rollback.

**Walk through:** What makes a committed credit discoverable if the process dies before starting
webhook delivery?

## Checkpoint 3: Expose final settlement without claiming host credit

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Return the existing result on replay. Keep final credit immutable and delivery
acknowledgment separate. Ensure independent drain B can credit while A's settlement remains pending.

**Check:** Generate duplicate completion orderings (I4); assert J2.S5.c14/J3.S5.c15/J8.S7.c4–c5 and
J6.S1.c14 with the downstream allocator. Reconcile debit, fees, deductions and backing.

**Walk through:** Which state can say the business received the funds while the user's account
update is still pending?

**Out of scope:** Host balance mutation and a general treasury ledger.

## Done and handoff

Database-backed allocation and outbox checks pass. A committed internal credit still requires signed
delivery and a committed host acknowledgment.

**Keep as evidence:** One balance equation for each entry path and the real transaction that
protects it.

Use exact criterion/invariant IDs in tests; see the shared protocol for naming,
merge checks and the checkpoint handoff. Do not start the next task automatically.
