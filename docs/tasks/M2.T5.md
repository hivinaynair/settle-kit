## Checkpoint 1: Match the protected identity across chains

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Decode source and attested V2 messages with their different populated fields. Match the
contract-derived operation tag, source event, destination message consumption and native-USDC
transfer in the same execution. Cover direct Base forwarding too.

**Check:** Reject wrong domain/token/recipient, missing or changed tag, unsafe receipts and
multi-message ambiguity (J3.S5.c14, J8.S6.c1–c4/c8, I10). Prove repeated equal-amount burns match
correctly when their mints arrive out of order.

**Walk through:** Which fact ties this Base mint to this source burn without trusting an API's
success label?

## Checkpoint 2: Track the original message through service failures

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement persisted Iris permits and single-poller ownership. Handle pending responses,
deployment-wide 429 pause and attention recheck spacing. Preserve the original burn at Standard
fallback and during forwarding failure.

**Check:** Race pollers across workers; test J4.S3.c3–c7 and J4.S4.c3–c6. A stalled forwarding
report cannot create another burn, credit or lost-funds verdict.

**Walk through:** Why is a per-process rate limiter insufficient when two workers recover the same
deployment?

## Checkpoint 3: Record the first combined real route

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Use built contracts and submitter for an actual Arbitrum testnet browser authorization
with zero payer ETH, through Circle Forwarding to independently verified Base arrival. Validate the
composed hook's deployed compatibility.

**Check:** Record explorer identities, tags, executed fees/finality and source submission/safe plus
Base arrival/safe times (J11.S1.c3/c9–c10). Browser signing is Vinay's action; an unavailable
signer/service leaves this gate unmet.

**Walk through:** Explain the proof from receipts, then state exactly what it has not proved about
SDK credit or host acknowledgment.

**Out of scope:** SDK re-attestation/mint submission, Relay fallback and treating the initial route
proof as full SDK credit proof.
