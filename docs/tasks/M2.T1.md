# M2.T1: Run recoverable work with bounded transaction submission

Status: planned; no implementation in this change.

**Outcome:** A restarted worker resumes the same action without losing transaction identity or
exceeding host spending limits.

**Learn:** Durable workflows, fencing, nonces, cost reservations and evidence-based terminal states.

- Depends on: [M1.T2](M1.T2.md), [M1.T3](M1.T3.md).
- Primary journey ownership: J1.S5a, J6.S2, J8.S5, J8.S11.
- Policy: D36, D111, D128, D139, D230. Invariants: I1, I5, I12.
- Rough effort: 4–6 focused developer days, excluding external waits.
- Expected locations: packages/server/src/workflows, submissions and budgets.

## Checkpoint 1: Run and recover a claimed stage

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement start(), explicit DBOS compatibility version, executor heartbeat and expiring
generation-fenced claims. Persist sleep deadlines and recover due work from application records.
Register schedules while chain adapters are still controlled fixtures.

**Check:** Kill a worker and revive it after a new worker claims the operation
(J6.S2.c5/c6/c11–c13). Unsupported pending workflow versions must fail readiness (J1.S5a.c12).

**Walk through:** What survives a process restart, and what stops its old worker from advancing
state?

## Checkpoint 2: Persist and bound every submission

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Reserve signer nonce and conservative gas/data-fee cost before signing/broadcast. Retain
replacement hashes and unknown-outcome holds. Implement shared ensure_contract deployment actions
used by manual and wallet commands, including original-deadline rechecks.

**Check:** Crash after reservation, signing, deployment broadcast and payment broadcast. Race
deployment requests. Prove original-transaction recovery and spend bounds (D139, J8.S5.c10/c14–c18,
I12); controlled evidence does not prove live scans.

**Walk through:** Why are workflow ID, operation claim, relayer nonce and USDC authorization nonce
four different things?

## Checkpoint 3: Close only payments proven unable to debit

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement the D111 transition using the chain adapter's complete source-safe
execution/cancellation evidence. Close the operation and its attention episode atomically; keep
unknown history pending. Reconcile any outstanding relayer attempt separately.

**Check:** Exercise J8.S11.c1–c5 and J6.S2.c17: revert, server-clock expiry and nonce consumption
alone are insufficient. Verify pending delivery/read-only work continues during spending pauses
(J6.S2.c16).

**Walk through:** Why can a reverted transaction leave the same payer authorization usable?

**Out of scope:** A new queue service, automatic re-signing or automatic conversion of collected
USDC to ETH.
