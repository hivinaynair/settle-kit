Status: planned; no implementation in this change.

**Outcome:** A separate consumer and independent setup attempt prove the shipped integration can
actually be used.

**Learn:** Package distribution, integration testing, workflow upgrades and reproducible evidence.

## Checkpoint 1: Install built packages outside the monorepo

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Add the actual package build/exports, archive packages and install them outside workspace
resolution. Run real account/operator authorization, shipped migrations, long-running startup and
atomic host webhook handling.

**Check:** Exercise simulated manual/wallet flows, pre-transfer reload and duplicate delivery
without chain credentials (J11.S1.c1/c5–c6/c8). Verify published widget dependencies and CSS
variables (D42).

**Walk through:** Which workspace conveniences could hide a broken consumer installation?

## Checkpoint 2: Complete route and upgrade recovery evidence

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Run the actual Base and Arbitrum testnet flows through host acknowledgment, retaining
M2.T5 evidence. Kill/restart at submission and delivery boundaries. Upgrade a pending operation
compatibly, then finish an old workflow beside a new incompatible name.

**Check:** Record J11.S1.c3/c9–c11 stage times and receipts. Run the full repository/Foundry checks
and check-journeys -- --complete. Review assertions as well as citation coverage.

**Walk through:** Which recovery proof depends on durable application identity, and which depends on
retaining compatible workflow code?

## Checkpoint 3: Have another developer follow the setup

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Replace the integration sketch only when it is runnable. Give an independent developer
the documented setup; record missing steps and correct them. Cross-check all task handoffs and
evidence limitations.

**Check:** Complete J11.S1.c7 and document the run. A missing volunteer, signature or service is an
unmet gate, never a simulated pass. Preserve explicit testnet/mainnet evidence labels.

**Walk through:** Could that developer reproduce the flow without Vinay explaining an unwritten
step?

**Out of scope:** Formal npm launch, mainnet readiness claims and declaring onboarding proven
without an independent run.

## Done and handoff

All required implementation, live-route and independent-onboarding gates have evidence. Missing
external prerequisites keep the relevant gate open.

**Keep as evidence:** The runnable consumer, reproducible setup log, route receipts and
package-upgrade recovery record.

Use exact criterion/invariant IDs in tests; see the shared protocol for naming,
merge checks and the checkpoint handoff. Do not start the next task automatically.
