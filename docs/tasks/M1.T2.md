# M1.T2: Create the durable store and shipped migrations

Status: planned; no implementation in this change.

**Outcome:** Postgres can preserve the identities and atomic writes that later workers need to
recover safely.

**Learn:** SQL migrations, unique constraints, transactions and conditional updates.

- Depends on: [M1.T1](M1.T1.md).
- Primary journey ownership: J1.S3.
- Policy: D22, D23, D30, D31, D36, D129, D139, D230. Invariants: I1, I4, I8, I10.
- Rough effort: 2–3 focused developer days, excluding external waits.
- Expected locations: packages/server/src/store; packages/server/migrations.

## Checkpoint 1: Create only the records with a recovery purpose

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Build the design's record groups with integer numeric columns, retained chain evidence
and explicit uniqueness. Separate SDK commands from observed drain settlements, and add the shared
deployment action key. Keep DBOS-owned tables separate.

**Check:** Apply and rerun numbered migrations against real Postgres (J1.S3.c1–c2). Reject a changed
applied migration under D30. Inspect each unique key with Vinay, including chain/tx/log and
chain/signer/nonce.

**Walk through:** Why can two observed drains exist while only one SDK manual-sweep command is open?

## Checkpoint 2: Make related writes succeed or roll back together

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement narrow transactions for acceptance, completed scan ranges, source/backing
claims, credit plus outbox, and repayment closure. Keep manual source ownership keyed to the drain,
not the submitting worker.

**Check:** Use real concurrent transactions and injected failures for I1, I8 and I10. Race source
and backing claims; a failed credit transaction leaves no partial allocation, credit or event.

**Walk through:** If the process dies after writing a credit but before its event, what forces both
writes to roll back?

## Checkpoint 3: Fence stale workers and freeze final credits

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Add conditional stage changes using claim generations, deployment-action reuse, signer
nonce reservation and the chain-pause lock. Limit updates to the operation's expected state.

**Check:** Generate stale-worker and duplicate-write orderings for I4/I10. Race a chain pause
against credit creation and a wallet/manual pair requesting the same deployment.

**Walk through:** Why is a worker claim different from a database transaction or a blockchain nonce?

**Out of scope:** Workflow scheduling and a general accounting ledger.

## Done and handoff

Migrations and transaction boundaries pass on real Postgres. Scheduling, chain interpretation and
live payment correctness remain later integration work.

**Keep as evidence:** One small record diagram and a walkthrough of the SQL constraint protecting
each money identity.

Use exact criterion/invariant IDs in tests; see the shared protocol for naming,
merge checks and the checkpoint handoff. Do not start the next task automatically.
