## Checkpoint 1: Persist and verify receive-account setup

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Store the unique winning vault/settings/ATA record and discovery start before setup
submission. Use the host SOL setup action, create saved refund/fee ATAs idempotently and verify
finalized initialized accounts before returning ready instructions. Expose pending/unavailable
distinctly.

**Check:** Race first requests and correct third-party setup, change server config, fail setup and

## Checkpoint 2: Build complete finalized instruction discovery

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Capture a produced finalized boundary; paginate vault/ATA/program activity and fetch full
supported transactions and canonical block order. Persist confirmed observations separately. Decode
pinned token transfers, program events and CCTP message accounts with signature/outer-inner
positions.

**Check:** Exercise J13.S3.c1–c6/c9–c10 and I8 with reversed same-slot signature ordering, missing
pages, pruned history, versioned lookup accounts, failed transactions and unavailable inner data.
Ambiguous skipped slots or gaps remain incomplete; establish archival coverage from saved start.

**Walk through:** Why is a token balance or successful signature lookup insufficient to identify the
source funds?

## Checkpoint 3: Integrate catch-up and shared scan scheduling

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Commit complete events/memberships/cursors atomically. Support new-address catch-up
behind the global cursor, targeted checks, third-party drains at zero balance and complete wallet

incomplete?
