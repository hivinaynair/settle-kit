# M3.T1: Reconcile books and finish narrow operator recovery

Status: planned; no implementation in this change.

**Outcome:** Operators can see incomplete books, resume stalled work and resolve narrowly defined
incidents with retained evidence.

**Learn:** Reconciliation, reorg risk, operational alerts and evidence-based recovery.

- Depends on: [M2.T7](M2.T7.md).
- Primary journey ownership: J6.S3, J6.S4, J7.S1, J7.S3, J8.S10, J10.S1, J10.S2, J12.S1, J12.S3, J12.S4, J12.S5, J12.S6.

## Checkpoint 1: Check all backing and report freshness honestly

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Reconcile credits, host residuals, shortfall funding and every treasury arrival,
including old stored recipients after config changes. Detect canonical evidence loss, retain credits
and pause affected chains. Record check boundaries and completeness.

**Check:** Exercise partial/failed/stale scans, unmatched arrivals and post-credit reorg
(J6.S3.c6–c16, I4/I10). A recent incomplete run cannot inherit a previous clean result.

**Walk through:** What does 'clean as of T' prove, and why can it become stale without any detected
bad payment?

## Checkpoint 2: Expose attention and the permitted operator actions

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement listAlerts/reconcile, keyed attention episodes and scheduled slow rechecking.
Supply authenticated scripts for exceptional funding and reorg acknowledgment; derive operator
identity from host authorization.

Keep detailed operator reasons while supplying the D114 next-actor/action category and existing
account-scoped case reference to client read models. A host-side problem cannot imply that the payer
should pay again. Add no support service, ticket system or public resolve API.

**Check:** Verify J6.S4, J8.S10 and J10.S1–S2. Reject customer/reused funding and missing
acknowledgment; spending pauses must preserve read-only recovery. Distinguish exhausted delivery
from unsettled money.

Check the reason/reference handoff for delayed/unknown, gas/spend-paused, forwarding/shortfall and
account-update-pending cases. M3.T2/M3.T3 test visible J8.S10.c6–c7 and J8.S8.c6 guidance.

**Walk through:** Why does finding extra treasury USDC not automatically prove a particular quote
shortfall is funded?

## Checkpoint 3: Close recovery cases with the correct evidence kind

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement J12 requests, external rescue observation, safe receipt verification and
unresolved cases. Feed both over_limit_usdc and asset_rescue cases into the same authenticated
repayment procedure. Keep USDC drain attribution separate from asset rescue.

**Check:** Prove J7.S3, J12.S1/S3–S6, including J12.S4.c6. Test both repayment labels,
unauthorized/partial closure, duplicate/crashed resolution and reconciliation after closure. New
contradictory evidence opens a linked investigation.

**Walk through:** Explain the difference between host recovery, a host-reported repayment and a
chain-verified transfer.

**Out of scope:** Automatic refunds, repayment initiation, asset portfolio discovery and a dashboard
product.

## Done and handoff

Operator recovery preserves credits, attribution and audit history. It cannot initiate refunds or
create a generic balance override; independent deployment evidence remains M4.T1.

**Keep as evidence:** A failure-and-recovery walkthrough with the alert, operator evidence and final
case state visible.

Use exact criterion/invariant IDs in tests; see the shared protocol for naming,
merge checks and the checkpoint handoff. Do not start the next task automatically.
