# M2.T7: Deliver signed events and commit host credit once

Status: planned; no implementation in this change.

**Outcome:** A lost webhook acknowledgment can retry without losing or duplicating the host's
account credit.

**Learn:** Signed raw-body delivery, at-least-once retries and host-side deduplication.

- Depends on: [M2.T6](M2.T6.md), [M2.T1](M2.T1.md).
- Primary journey ownership: J5.S1, J5.S2, J5.S3, J10.S3.
- Policy: D45, D124, D140, D230. Invariants: I1, I5.
- Rough effort: 2–3 focused developer days, excluding external waits.
- Expected locations: packages/server/src/webhooks; host receiver example and integration fixtures.

Read the linked [decisions](../decisions.md), exact criteria in the
[journey spine](../journeys/settle-kit.md), and [technical
design](../plans/2026-10-15-deposit-sdk-technical-design.md).
Use the [checkpoint protocol](README.md#how-we-implement-together). Implement one
checkpoint per turn unless Vinay explicitly asks for a longer run.

## Checkpoint 1: Deliver immutable events with bounded retries

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement Standard Webhooks signing/verification, saved event bytes, fresh attempt
timestamps and persisted timeout/retry state. Recover pending events even when their deposits are
already credited.

**Check:** Exercise J5.S1.c2–c8 and I5: exact retry budget, unchanged identity/body, no
secret/signature logs and no reset after restart. Attention events must never update a balance.

**Walk through:** Why does a retry need a fresh signature timestamp but the same event ID?

## Checkpoint 2: Commit the host's account update once

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement webhook(handler) with raw-body verification and awaited handling. Provide the
actual host transaction that inserts the unique event ID and updates one account balance; rollback
both on failure.

**Check:** Drop the response after host commit, deliver duplicates concurrently and force failure
before commit (J5.S2.c4–c8). Invalid/expired signatures cannot invoke the handler (J5.S2.c2).

**Walk through:** Why does verifying a valid signature not prevent a second balance update?

## Checkpoint 3: Make failed delivery visible and resendable

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Persist exhausted delivery and its alert. Wire operator-authorized resend to the same
event and reset only that delivery budget. Expose delivery separately from settlement.

**Check:** Exhaust, restart and explicitly resend (J5.S3.c1–c3, J10.S3.c1–c3). The host must return
success for an already committed event without another balance mutation.

**Walk through:** Which action can repair an exhausted delivery without changing the credit?

**Out of scope:** Email/Slack alerts and success before the host transaction commits.

## Done and handoff

Real database/HTTP integration proves lost-acknowledgment recovery. Reconciliation and the
independent consumer remain separate gates.

**Keep as evidence:** A two-transaction diagram showing SDK credit, host credit and the
acknowledgment that can be lost between them.
