## Checkpoint 1: Restore authoritative account history

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement useDeposits and usePayWithWallet over one controller and authenticated
transport. Recover accepted attempts before offering another payment, including an attempt with no
source transfer.

**Check:** Reload or change device without a cached paymentId and switch accounts during a response
(J8.S1.c6–c8, J8.S8.c5, J9.S1.c2–c3). Use the simulated server for early preview.

**Walk through:** Which state belongs in the browser, and which state must be restored from the
server?

## Checkpoint 2: Keep quote consent tied to the current selection

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement both editable amount directions, stale-response suppression and explicit
signing/submission. Handle connection rejection, unverified wallet capability, account/network
changes and unknown submission as different outcomes.

**Check:** Change selection while quotes and wallet prompts are outstanding (J8.S2.c8, J8.S3.c2–c5,
J8.S9.c1–c2, I12). Do not submit stale consent or turn a timeout into Pay again.

**Walk through:** What must be invalidated when the payer changes accounts while a signature prompt
is open?

## Checkpoint 3: Expose an accessible custom-interface model

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Expose actions/status/errors for a small hook-based consumer. Preserve settlement versus
host-delivery state, manual-option availability and the shared instruction guard. Document
CSS-variable boundaries without a broad component API.

**Check:** Exercise J8.S8.c1–c5 and J9.S2.c1–c4 in a custom interface, with keyboard/status
announcements. Controlled acknowledgment proves client behavior; live delivery closes in M4.T1.

**Walk through:** Can a developer using only hooks preserve every money and recovery rule the
prebuilt widget uses?

**Out of scope:** Wallet provisioning, a paymaster and untested claims of universal wallet support.
