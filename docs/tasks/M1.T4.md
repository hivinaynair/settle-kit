# M1.T4: Prepare immutable quotes in both amount directions

Status: planned; no implementation in this change.

**Outcome:** Either amount field produces one stored quote whose promised credit survives its
permitted fees.

**Learn:** Integer pricing, rounding, idempotency and signed consent.

- Depends on: [M1.T2](M1.T2.md), [M1.T3](M1.T3.md).
- Primary journey ownership: J8.S2.
- Policy: D110, D111, D113, D126, D128, D140, D141, D231. Invariants: I12.
- Rough effort: 2–3 focused developer days, excluding external waits.
- Expected locations: packages/server/src/quotes; packages/core amount and signing codecs.

Read the linked [decisions](../decisions.md), exact criteria in the
[journey spine](../journeys/settle-kit.yaml), and [technical
design](../plans/2026-10-15-deposit-sdk-technical-design.md).
Use the [checkpoint protocol](README.md#how-we-implement-together). Implement one
checkpoint per turn unless Vinay explicitly asks for a longer run.

## Checkpoint 1: Calculate both amount directions with one policy

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement the required versioned host fee policy and integer pay/receive calculation.
Read route limits and cost bounds; return debit, credit, disclosed fee and both deadlines. Refuse
unbounded pricing.

**Check:** Use D126/D141 tables for rounding, impossible fees, minimum/cap edges and expiresAt
before validBefore. Assert the display model supplies J8.S2.c3/c10/c12 fields.

**Walk through:** Why is the maximum Circle deduction subtracted before promising a credit?

## Checkpoint 2: Store one result for one preparation request

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Use the internal address-issuance interface to persist the recipient's complete
prediction and discovery start before signing data is returned. Atomically save the quote and
canonical-input hash under the preparation key; perform no deployment here.

**Check:** Race equal requests and reject conflicting reuse (J8.S2.c5–c6). Changed server
configuration cannot mutate the saved destination. Until M2.T2 integrates the live issuer, label its
controlled adapter evidence explicitly.

Repeat an expired preparation key and verify that the saved expired quote is returned without
repricing. A user-approved new preparation uses a new key; M3.T2/M3.T3 prove the preserved-input and
Review updated quote interactions in J8.S2.c14–c15.

**Walk through:** Why does an expired quote need a new key and fresh consent instead of an update to
the old row?

## Checkpoint 3: Bind signing data to the stored quote

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Build typed signing data using the M1.T3 commitment format, including payment identity,
fee split, amount bounds and original validity. Use the predicted recipient even when its code is
not deployed yet.

**Check:** Check mismatched chain, recipient, payer, fee and amount against J8.S3.c5/I12.
Preparation must refuse unavailable provider reads or a routine host top-up (J8.S2.c7/c11).

**Walk through:** Point to the data the user sees, the data they sign, and the immutable row that
relates them.

**Out of scope:** Hardcoded production fee/lifetime defaults and measured-gas refunds.

## Done and handoff

Both directions produce immutable, bounded consent. The live address-issuer integration closes in
M2.T2/M2.T4; signing and broadcasting remain later work.

**Keep as evidence:** A worked base-unit quote calculation and an explanation of submission cutoff
versus execution deadline.

Use exact criterion/invariant IDs in tests; see the shared protocol for naming,
merge checks and the checkpoint handoff. Do not start the next task automatically.
