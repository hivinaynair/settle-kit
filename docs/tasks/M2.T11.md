## Checkpoint 1: Decode and match source and destination evidence

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Verify finalized owned-program execution, pinned token/CCTP programs, message-account
data, protected tag, payer/manual amounts and fees. Reuse the composed-frame and Base-consumption
verifier without equating source bytes with off-chain-populated attestation fields.

**Check:** Reject changed tags/programs/domains/mint/recipient/fees and ambiguous equal-amount
messages arriving out of order (J13.S5.c1–c4/J14.S5.c1–c2/I10). A transaction signature or provider
success is not source-to-Base attribution.

**Walk through:** Which protected field distinguishes two otherwise identical burns?

## Checkpoint 2: Retain the original burn during failures and shortfalls

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Share M2.T5 persisted Iris limits and D17/D56 schedules. Track original Fast or Standard
execution and Base-safe canonicality, retaining source data if an event account is later reclaimed.
Supply verified proof to M2.T6, including quoted shortfall rather than partial credit.

**Check:** Check J13.S5.c3–c5/J14.S5.c3–c4 under 404, 429, timeout, forwarding failure, missing Base
arrival and shortage. No failure permits reburn, new payer consent or a provider-status credit.

**Walk through:** Why does a verified Solana burn still leave the account uncredited?

## Checkpoint 3: Record both real devnet-to-Base routes

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Use the built program and submitter for manual off-curve-owner/ATA receive and a
supported browser wallet transaction with zero payer SOL. Prove the deployed composed hook, message
size/compute and source-to-Base linkage; leave SDK/host-credit completion for M2.T6/M2.T7/M4.T1.

**Check:** Record J11.S1.c12–c14 source confirmed/finalized and Base arrival/safe stages, actual
fees, identities and wallet/version. Browser signing is Vinay’s action. Local validators/forks
cannot close this gate; unavailable signer/service remains unmet.

**Walk through:** Walk from the Solana transaction to the Base receipt, then identify what still
needs host-acknowledgment proof.

**Out of scope:** New SDK mint/re-attestation service, Solana treasury destinations, premature
mainnet claims and scripted-key substitutes for browser compatibility.
