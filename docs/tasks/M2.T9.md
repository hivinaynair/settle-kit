# M2.T9: Submit and attribute guarded Solana manual sweeps

Status: planned; no implementation in this change.

**Outcome:** One saved manual command burns one attributable drain without spending beyond host
limits or sweeping later funds on retry.

**Learn:** Recent blockhashes, transaction signatures, rent budgets, on-program sequences and
full-drain attribution.

## Checkpoint 1: Persist the exact host-funded transaction before broadcast

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Build setup/sweep actions from stored settings and the expected drain sequence. Reserve
bounded base/priority fees and rent, save operational event-account signers securely and persist
signed bytes/signature/blockhash/lastValidBlockHeight before sending.

**Check:** Crash before/after signing and broadcast, race workers and exhaust each budget
(J13.S4.c7–c10/I5). A timeout retains the action and reservation. An identical rebroadcast does not
double-reserve fees.

**Walk through:** How do a transaction signature and an expected drain sequence protect different
boundaries?

## Checkpoint 2: Apply manual amount and source-membership guards

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Enforce minimum/cap/live burn-limit/fee checks through the owned program. Discover actual
drain execution, reconstruct canonical memberships and distinguish an external drain from the SDK
command. Preserve raw CCTP message data before event-account reclaim can remove it.

**Check:** Prove J13.S4.c1–c6 with top-ups, equal-amount drains, external drain B while command A is
unknown, quote-vault isolation and gross/fee/burn mismatch. A recovered transfer can never enter a
later credited drain.

**Walk through:** Why does the emitted drain balance need to agree with the incoming transfer
membership sum?

## Checkpoint 3: Recover expired host-only actions without retargeting them

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Rebroadcast identical valid bytes. Refresh a host-only blockhash only after finalized
expiry and complete no-execution proof; retain operation and expected sequence. If another caller
already consumed it, reconcile that drain and do not retarget A to the next sequence. Resume
original-message verification after success.

**Check:** Exercise J13.S4.c8–c10 across timeout, crash, old transaction landing, expiry and a later
deposit. Verify an old command cannot sweep the later batch and cannot reburn after source success.
Supply receipts to M2.T11.

**Walk through:** What must be proven before changing a host-only transaction blockhash, and why is
wallet consent stricter?

**Out of scope:** Automatic payer signing, SDK recovery submission, destination minting and
provider-status credit.
