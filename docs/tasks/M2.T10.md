# M2.T10: Prepare and recover exact Solana wallet transactions

Status: planned; no implementation in this change.

**Outcome:** A payer signs one bounded USDC payment without SOL; durable acceptance and expiry
recovery preserve that exact consent.

**Learn:** Transaction messages, Ed25519 signatures, fee-payer co-signing, atomic CPI and no-debit
proof.

- Depends on: [M1.T4](M1.T4.md), [M2.T4](M2.T4.md), [M2.T8](M2.T8.md), [M2.T9](M2.T9.md).
- Primary journey ownership: J14.S1, J14.S2, J14.S3, J14.S4, J14.S8, J14.S10.
- Policy: D117, D137, D143, D233; D110–D115, D126, D128, D140, D141. Invariants: I1, I5, I11, I12.
- Rough effort: 3–5 focused developer days, excluding external waits.
- Expected locations: Server Solana quote/acceptance adapter and wallet signing envelope; controller integration contracts.

Read the [decisions](../decisions.md), exact [journey criteria](../journeys/settle-kit.yaml),
and the Solana section of the [technical design](../plans/2026-10-15-deposit-sdk-technical-design.md).
Follow the [checkpoint protocol](README.md#how-we-implement-together): one checkpoint per turn,

## Checkpoint 1: Prepare one exact transaction and signing contract

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Reuse M1.T4 pricing/idempotency with the Solana IDL. Store all fixed accounts, required
signers, recent blockhash lifetime and quote deadlines. Bound transaction size/account
count/compute; validate any needed lookup tables and account resolution. Return only payer-signable
message data, with no host co-signatures.

**Check:** Check J14.S1.c1–c6/J14.S2.c1–c4 using changed cluster, payer, message, fee payer,
instructions and expired blockhash. Wallet mutation/signAndSend is refused. M3.T2/M3.T3 prove actual
consent, history-first and preserved-input interactions.

**Walk through:** Which saved bytes are the payer consenting to, and why can the host not silently
change the priority fee?

## Checkpoint 2: Accept durably then co-sign and resume the original action

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Verify the payer signature against the saved message and host-authorized account. Commit
acceptance before adding operational signatures or broadcasting. Resume the same payment ID after
lost acknowledgment; use M2.T9 persistence/spend machinery and M1.T5 isolated payment vault/receipt.

**Check:** Race acceptance and conflicting/repeated signatures (J14.S3.c1–c5). Inject crashes at
acceptance, co-signing and broadcast. Assert J14.S4.c1–c7, including zero-SOL payer, failed CPI with
no USDC fee, manual isolation and no secret-bearing output.

**Walk through:** Why must the host signature be withheld until acceptance is committed?

## Checkpoint 3: Prove expiry without inventing a second payment

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Use M2.T8 complete finalized history plus the permanent program receipt and finalized
block height to implement J14.S10. Accepted expired messages are not refreshed; new consent is
explicit only after no-debit proof. Keep unknown attempts, spend reservations and source-success
history distinct.

**Check:** Exercise J14.S8.c1–c2/J14.S10.c1–c3 with null lookups, missing archival pages,
just-before/after lastValidBlockHeight and successful original execution discovered late. A
wall-clock timeout cannot show No USDC was charged.

**Walk through:** Why does blockhash expiry alone not prove that the original payment did not
already execute?

**Out of scope:** Standing token delegates, automatic re-signing, EVM typed-data on Solana and
generic transaction submission APIs.
