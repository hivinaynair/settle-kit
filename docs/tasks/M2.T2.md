# M2.T2: Issue stable addresses and index complete chain ranges

Status: planned; no implementation in this change.

**Outcome:** Issued addresses stay stable and complete chain scans discover events regardless of who
submitted them.

**Learn:** Indexing, pagination, cursors, provisional evidence and canonical block hashes.

- Depends on: [M1.T2](M1.T2.md), [M1.T3](M1.T3.md), [M2.T1](M2.T1.md).
- Primary journey ownership: J2.S3, J3.S3, J6.S1.
- Policy: D21, D34, D121, D131, D134, D135, D140. Invariants: I8, I10.
- Rough effort: 3–4 focused developer days, excluding external waits.
- Expected locations: packages/server/src/addresses and chain/scanner.

Read the linked [decisions](../decisions.md), exact criteria in the
[journey spine](../journeys/settle-kit.md), and [technical
design](../plans/2026-10-15-deposit-sdk-technical-design.md).
Use the [checkpoint protocol](README.md#how-we-implement-together). Implement one
checkpoint per turn unless Vinay explicitly asks for a longer run.

## Checkpoint 1: Persist the address before returning it

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Implement the shared address-issuance service used by manual instructions and quote
preparation. Save prediction inputs and scan start atomically; validate the factory manifest and
existing code. Read saved records after configuration changes.

**Check:** Race first requests, change config and catch up a new address behind the global cursor
(J2.S1.c5–c7, J6.S1.c8/c10–c11). Integrate M1.T4's live address issuer.

**Walk through:** Why is deriving an address again from today's configuration unsafe?

## Checkpoint 2: Commit only fully read ranges

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Capture each chain's safe block/hash, read every required RPC page and commit events plus
range cursor together. Keep account-targeted catch-up separate from global progress. Expose latest
observations separately from safe records.

**Check:** Fail a middle page, overlap scans and remove a provisional transfer in a replacement
block (I8, J2.S3.c5–c6, J6.S1.c4–c7). An incomplete scan must leave its cursor unchanged.

**Walk through:** What does this cursor prove, and which blocks does it say nothing about?

## Checkpoint 3: Discover drains and supply complete payment history

- [ ] Reviewed with Vinay; focused checks and remaining evidence recorded.

**Build:** Index third-party sweeps, recoveries, rescues and quoted executions even at zero balance.
Create independent observed-drain settlements while an SDK command remains open. Supply complete
source execution/cancellation scans to M2.T1.

**Check:** Read B's external drain before A's earlier drain, exclude exact wallet transfers from
manual attribution, and check J6.S1.c9/c12–c14. Implement the D131 scan cadences. Include retained
block hashes in evidence.

**Walk through:** How do you find an externally swept payment when the address's current balance is
zero?

**Out of scope:** RPC activity webhooks, additional chains and history inferred from token symbols.

## Done and handoff

Address issuance and scans satisfy their range/identity checks. Network outages remain observable
incomplete work; source attribution and credits close in later tasks.

**Keep as evidence:** A captured-range diagram and a walkthrough of one externally submitted event
becoming a stored settlement candidate.

Use exact criterion/invariant IDs in tests; see the shared protocol for naming,
merge checks and the checkpoint handoff. Do not start the next task automatically.
